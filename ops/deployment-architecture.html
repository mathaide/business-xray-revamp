● Reference architecture · ~100 users · central analysis & decisioning · India

Business X-Ray — production deployment

From today's client-side demo to a governed platform: a thin client in the field, a central "decipher" server that runs multimodal extraction → the Business X-Ray engine → external triangulation → decision-support, and a human review console. Toggle the one big fork — how the AI model runs — to see how the server footprint changes.

What the client needs

Almost nothing. A modern browser (Chrome/Safari) on an Android phone or laptop, camera permission, and internet. Ship it as an installable PWA for an app-like feel with offline capture + background sync. No VM, no install on the client.

Optional later: a thin Android wrapper for store distribution / device policies.

What you run (server)

One central server (VM or managed container) hosting the API, the extraction + engine + decision modules, Postgres, encrypted object storage, auth and audit — plus an underwriter console. Add a GPU node only if you self-host the AI model.

Put it in an India region (Mumbai) for data residency.

Does it need a VM?

Yes (or a managed equivalent). With hosted AI, a modest CPU VM is enough — the model is an API call. With self-hosted AI (Ollama/Qwen-VL, sovereign), add a GPU VM. For 100 users the scale is small either way.

Managed containers (Render/Railway/ECS/Cloud Run) work too — a VM is not mandatory, just the simplest mental model.

3 · Central "decipher" server — the core module

Ingestion + consent

Receives photos/context; records purpose-limited consent (DPDP/AA).

Multimodal extraction — g(·) VLM API

Reads photos/docs → GSTIN, meter no., VPA, amounts, counts + confidence.

Business X-Ray engine

Scenario intervals, simplified P&L, WCR/trade cycle, IRI, next-evidence.

External triangulation

Account Aggregator (via regulated TSP), GST, utility, Perfios — concordance/conflict.

Decision-support

Deterministic rules engine + validated scorecard → recommendation & reason codes. Never auto-approves.

Human review console

Underwriter queue: evidence graph, overrides, sanction; borderline/vulnerable → human.

Governance

Model registry/versioning, full audit log, reason codes, override tracking.

Notifications

Voice/SMS/WhatsApp (Twilio/Sarvam) — reminders, status, financial literacy.

▼
4 · Data & secrets

Postgres

Cases, evidence graph, decisions, audit.

Object storage (encrypted)

Photos/docs; retention + deletion policy.

Secrets vault

API keys, DB creds, AA tokens.

Backups + monitoring

Snapshots, logs, alerts.

Compliance overlay (spans everything): DPDP Act 2023 (consent, minimisation, retention, deletion) · RBI Digital Lending Directions 2025 + FREE-AI (auditable assessment, explainability, human accountability) · Account Aggregator Master Direction (granular, revocable consent). The regulated lender retains final accountability.

Sizing for ~100 users

100 field users ≈ 10–20 concurrent, tens–low-hundreds of cases/day. This is small — one well-sized node plus managed Postgres carries it.

Phased rollout from today's demo

1

Backend + auth

Stand up FastAPI + Postgres on a VM; move the engine + audit server-side; add OIDC roles; persist cases. (Current static app becomes the PWA front-end.)

2

Real extraction + console

Wire the VLM (API or Ollama/Qwen-VL) for g(·); build the underwriter review/override console.

3

Consented data + decisioning

AA (via TSP) + GST + utility + Perfios; rules engine + validated scorecard; reason codes.

4

Harden & scale

Encryption, backups, monitoring, pen-test, DPDP/RBI sign-off; roll out to 100 users.

5

Sovereign option

Swap hosted model for on-prem/GPU Qwen-VL if data-residency demands it — same interface.

6

Voice layer

Add Sarvam for Marathi/Hindi voice application + reminders (Twilio telephony).

Indicative reference architecture for a ~100-user pilot as of Aug 2026; component choices and sizing should be validated against your actual volumes, security review and regulatory sign-off. Business X-Ray outputs remain human-supervised first-pass assessments — not a validated credit-scoring model, and never an autonomous credit decision.
